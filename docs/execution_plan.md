# Execution plan

## Phase 0 — Repository bootstrap

- Establish the Python package, environment, tests, and Make targets.
- Preserve original data and previous proposal artifacts.
- Document provenance, protocol, collaboration, and decisions.
- Configure a public GitHub repository after local review.

## Phase 1 — Data audit

- Validate schema, types, ranges, missingness, duplicates, timestamps, factor
  levels, and `cnt = casual + registered`.
- Report hourly gaps and factor balance.
- Decide how to handle the three observations at weather level 4 without
  changing the raw file.

**Completion criterion:** The validation script fails clearly on malformed data,
all checks are tested, and a machine-readable audit table is generated.

## Phase 2 — Descriptive analysis

- Produce summary statistics, distributions, boxplots, time plots, grouped
  means with confidence intervals, and numerical correlations.
- Establish consistent, publication-ready plotting conventions.

**Completion criterion:** Every reported number and figure is generated by one
command and has an explicit source script.

## Phase 3 — DOE analysis

- Freeze the analysis protocol before interpreting confirmatory tests.
- Plot and estimate main effects.
- Test the primary `workingday × hr` interaction.
- Evaluate secondary interactions as exploratory analyses.
- Report multiplicity-aware comparisons and effect sizes.

**Completion criterion:** Statistical tables, effect plots, interaction plots,
and an interpretation draft are reproducible.

## Phase 4 — Assumptions and explanatory modeling

- Compare raw, square-root, and log-one-plus response scales.
- Evaluate residual distribution, variance, temporal dependence,
  multicollinearity, leverage, and influence.
- Compare hierarchical models and temporally adjusted uncertainty estimates.

**Completion criterion:** The response scale, covariance correction, and final
explanatory model are justified in the decision log.

## Phase 5 — Predictive validation

- Implement expanding-window validation and a final end-of-2012 holdout.
- Compare models with a simple historical baseline.
- Report MAE, RMSE, out-of-sample R-squared, and subgroup errors.

**Completion criterion:** The untouched holdout is evaluated once after model
selection, and the predictive-model decision is documented.

## Phase 6 — Paper and presentation

- Write the SBC article alongside the analysis.
- Select only figures and tables that support the research question.
- Perform a clean-environment reproduction before submission.
- Tag immutable proposal, draft, submission, and presentation milestones.

## Planned commit sequence

```text
chore: initialize reproducible project structure
feat(data): validate hourly observations
analysis: add descriptive statistics and plots
analysis: evaluate main effects and interactions
analysis: compare response transformations
feat(model): compare explanatory regression models
feat(validation): add chronological model evaluation
docs(paper): report statistical and predictive results
docs(slides): add final presentation
release: prepare assignment submission
```
